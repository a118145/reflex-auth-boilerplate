# Secure multi-user apps (Reflex auth boilerplate)

Two things in one skill:

1. **An architecture** for any app in which several people sign in and own
   data: `references/architecture.md`. Framework-neutral rules, each closing
   a hole that was found in a production app, plus a review checklist. Use
   it on its own when the question is "is this multi-user app designed
   safely?" or when the same design is needed on another stack.
2. **Its implementation for Reflex**, retrofitted onto an app generated by
   the companion skill
   [reflex-app-scaffold](https://github.com/a118145/reflex-app-scaffold).

The result of applying it:

- **Every page and every event handler requires a signed-in user**, with no
  exceptions except the landing page (`/login`), the admin login
  (`/admin-login`) and `/forbidden`. New pages are protected automatically.
- Users sign in with a **magic link** mailed to an address on an allowed
  domain. Accounts are created on first sign-in.
- One **admin** signs in with e-mail + password (environment only) at an
  unlinked route. A magic link never yields admin rights.
- An **admin area**: dashboard, accounts (block/unblock, merge two addresses
  into one person, delete with hand-over of data), groups, live sessions
  (end them), audit log.
- A **service layer** (`service/`): use cases that take the acting user's id
  and check what that user may see or do; handlers reach the database only
  through it. **Ownership and sharing** — with a person, a group, everyone —
  are implemented once and applied to a table by declaration.
- **Guard tests** that keep it that way: the public surface, which handlers
  carry which check, no query outside the service, every person column
  covered by merge and delete, what an event may say about who is signed in.
- A daily lifespan task deletes spent links, ended sessions and old login
  attempts (`AUTH_PURGE_AFTER_DAYS`, default 30); the audit log is kept.

**Read before changing anything**, in this order:

| File | For |
| --- | --- |
| `references/architecture.md` | The rules and why — the design every later change must keep. |
| `references/security_model.md` | How Reflex implements them; known limits. |
| `references/reflex_auth_facts.md` | Verified Reflex 0.10.1 behaviour the code rests on. Several obvious approaches leak the session token or do not work. |
| `references/ownership_and_sharing.md` | The recipe for Step 6: making a table owned and shareable. |
| `references/deployment.md` | One https origin, proxy, headers, mail, backup. |

Also read the scaffold's own `references/reflex_098_gotchas.md` if it is
available.

## Non-negotiables

These are the reason the skill exists. Do not "simplify" them away.

1. **No token, key or password in a public state var — ever.** The session
   token lives only in an HttpOnly cookie; the backend keeps its SHA-256 in
   a `_private` var. Never read `router.headers.cookie`.
2. `AuthMiddleware` is registered at **index 0**. It strips the cookie from
   the router data (Reflex serialises router headers to the browser) and
   gates every event.
3. Sign-in/out are **HTTP endpoints** (`/_auth/*`) driven by `native_form`
   posts, not Reflex events or `rx.form`.
4. The magic link's `GET` only shows a button; the `POST` spends the token
   (mail scanners prefetch links).
5. Links and redirects are built from `api_url`/`deploy_url`, never from
   anything the browser sends. `redirect_to` is same-origin paths only.
6. Authorization is declared in `auth/policy.py` (`PUBLIC_ROUTES`,
   `ROUTE_CHECKS`, named decorators), never as `if` in a handler — and
   **enforced again in `service/`**, which takes the acting user's id.
7. **The Reflex client token is not a credential.** Only an event that
   arrived on a socket says anything about the cookie
   (`middleware.event_origin`); uploads need a grant (`upload_gate`).
8. **Handlers do not query.** States reach the database only through
   `call(service.use_case, actor, ...)`.
9. **Reflex is pinned to 0.10.1.** The gate rests on private Reflex
   behaviour; 0.11 changes some of it (`references/reflex_auth_facts.md`).

## Step 1 — Inspect the target app

Confirm it is a scaffold app and read off what the templates need. **Ask
nothing the code already answers.**

| Fact | Where |
| --- | --- |
| `app_name` | `rxconfig.py` → `app_name="…"` |
| layout | `ui/nav.py` + `ui/side.py` → `both`; only `nav.py` → `top`; only `side.py` → `side` |
| database | `db_url=` in `rxconfig.py` and an `alembic/` folder |
| `app_title` | the `rx.heading("…")` wordmark in `ui/side.py` (or `ui/nav.py` for `top`) |
| Reflex version | `uv pip list` → `reflex` |
| modules that query | `grep -rlE "rx\.session|from sqlmodel|from sqlalchemy" <app_name>` minus `models/` → `{{legacy_modules}}` |

Also check, and stop to ask if any is true:

- `auth/`, `service/`, `pages/login.py`, `ui/account.py`, `utils/db.py`,
  `tests/conftest.py` or a `/login` route already exist.
- **Reflex is not 0.10.1.** A fresh scaffold installs the newest release.
  Tell the user that the auth code is verified for 0.10.1 only and that
  Step 3 will pin it; if the app already depends on a newer Reflex feature,
  stop — do not adapt the templates to another version on the fly.
- `git status` is dirty — ask whether to proceed (the edits touch scaffold
  files the user may have changed).
- The anchors in Step 4 are not found verbatim — the user changed the
  scaffold files. Read the file, apply the *intent* of the edit by hand, and
  tell the user what you did.

## Step 2 — Interview

**One `AskUserQuestion` call, three questions.** Do not ask which pages to
protect: all of them are, by design (see Non-negotiables); say so in the
restatement.

1. **Slogan and logo** for the landing page. Offer a neutral default slogan;
   the logo is optional (a file the user names, copied into `assets/`; default
   is the scaffold's `box` icon). Use previews only if it helps.
2. **Allowed e-mail domains** for magic links — exact domains,
   comma-separated (subdomains are *not* included). No default domain;
   require an answer.
3. **Mail transport** to preconfigure in `.env.example`: `smtp` (e.g. a
   Microsoft 365 mailbox), `graph` (Microsoft Graph, app-only), `mailgun`, or
   `console` (development only — logs the link, refused in prod). All four are
   always generated; this only picks the default.

Restate the plan (layout, DB retrofit yes/no, Reflex pin, domains,
transport, routes added, that every page will require login, and that
existing data stays shared between all signed-in users until Step 6) before
changing files.

## Step 3 — Reflex version and database

Pin Reflex — this also adds the database extra (magic links need tables) and,
since 0.10, `greenlet`:

```bash
uv add "reflex[db]==0.10.1"
scripts/check.sh            # the app must still be green before auth goes in
```

If the app has **no database**, add to `rxconfig.py` `import os` above
`import reflex as rx` and, inside `rx.Config(...)`, directly below
`app_name=`:

```python
    db_url=os.environ.get("REFLEX_DB_URL", "sqlite:///reflex.db"),
```

Then, for **every** app:

```bash
[ -d alembic ] || uv run reflex db init
```

Do **not** create `models/` for a database-less app: the auth tables live in
`auth/models.py`, the group tables in `service/models.py`.

## Step 4 — Copy and wire

### 4a. Copy templates

Copy `templates/` into the app. `tests/*` go to the project's `tests/`,
everything else into the `{{app_name}}/` package, keeping sub-paths. Strip
`.tmpl` and fill placeholders. Never overwrite an existing file.

| Placeholder | Value |
| --- | --- |
| `{{app_name}}` | package name |
| `{{app_title}}` | the wordmark text |
| `{{slogan}}` | a Python string literal — write it with `repr()` semantics (escape quotes) |
| `{{logo}}` | `None`, or a literal like `"/logo.svg"` (file copied to `assets/logo.svg`) |
| `{{show_admin_subnav}}` | `True` for layout `top`, else `False` |
| `{{legacy_modules}}` | a Python set literal of the modules found in Step 1, relative to the package: `{"states/item_detail_state.py", "states/items_state.py"}` for a scaffold app with the CRUD demo, `set()` without a database |

Grep the copied files for `{{[a-z_]+}}` afterwards — nothing may survive.
(`auth/endpoints.py` contains CSS braces; those are not placeholders.)

### 4b. Edit scaffold files

Snippets live in `snippets/`. Each edit names its exact anchor in the
scaffold's original text.

1. **`navigation/routes.py`** — append `snippets/routes_append.snippet`.
2. **`navigation/nav_config.py`**
   - In `class NavItem`, after the `sub_items: …` line, insert
     `snippets/nav_item_admin_only_field.snippet`.
   - Append to `NAV_ITEMS` (last entry): `nav_admin_entry_top.snippet` for
     layout `top`, otherwise `nav_admin_entry_sections.snippet`.
3. **`ui/` — admin entry visible to the admin only, account block at the end
   of the navigation.**
   - `top` (`ui/nav.py`): import
     `from .account import account_block_inline, admin_only`; wrap
     `navbar_item(item, i)` as `admin_only(item, navbar_item(item, i))`;
     in the `left` branch insert `account_block_inline(),` between
     `rx.spacer(),` and `rx.color_mode.button(),`; in the `center` branch
     replace the absolutely positioned `rx.color_mode.button(position=…)` by
     an `rx.hstack(account_block_inline(), rx.color_mode.button(),
     align="center", spacing="3", <same position props>)`.
   - `side` (`ui/side.py`): import
     `from .account import account_block_vertical, admin_only`; wrap
     `_section(item)` as `admin_only(item, _section(item))`; insert
     `account_block_vertical(),` right after the existing `rx.spacer(),`
     (above the colour-mode toggle).
   - `both`: in `ui/nav.py` import `from .account import admin_only` and wrap
     `navbar_item(...)` as above. In `ui/side.py` import
     `from .account import account_block_vertical, admin_only`, wrap the
     `rx.cond(NavState.active_section == index, …)` inside `sections` as
     `admin_only(item, rx.cond(…))`, and after `*sections,` insert
     `rx.spacer(),` and `account_block_vertical(),` — the account block sits
     at the bottom of the sidebar.
4. **`pages/__init__.py`** — import and list in `__all__`: `admin_audit`,
   `admin_dashboard`, `admin_groups`, `admin_login`, `admin_sessions`,
   `admin_users`, `forbidden`, `login`.
5. **App module `{{app_name}}/{{app_name}}.py`** — after `from . import pages`
   insert `snippets/app_module_imports.snippet` (its first line,
   `from reflex.model import ModelRegistry`, belongs with the third-party
   imports — `ruff check --fix` sorts it); replace `app = rx.App()` with
   `snippets/app_module_app.snippet`. Update the module docstring: it now also
   wires authentication.
6. **`tests/test_routes.py`** — add `snippets/expected_routes.snippet` to
   `EXPECTED_ROUTES`.
7. **`utils/casting.py`** — append `snippets/casting_as_id.snippet`
   (`InvalidInput`, `as_id`).
8. **`rxconfig.py`** — CORS for the app's own origins instead of `*`: add
   `from urllib.parse import urlsplit` below `import os`, insert
   `snippets/rxconfig_own_origins.snippet` between the imports and
   `config = rx.Config(`, and add `cors_allowed_origins=_own_origins(),`
   inside `rx.Config(...)` below the `db_url=` line.
9. **`states/__init__.py`** — leave as is (the admin state is imported by its
   module path). If it is missing, create the scaffold's docstring-only one.

### 4c. Migration, configuration, docs

```bash
uv run reflex db makemigrations --message "auth tables"
uv run reflex db migrate
```

- Write `.env.example` from `snippets/env.example.tmpl`
  (`{{allowed_domains}}`, `{{mail_transport}}`, `{{app_name}}`) and append
  `.env` to `.gitignore`. Never write real secrets anywhere in the repo.
- Do not hard-code `api_url` or `deploy_url` in `rxconfig.py`: where the app
  is reachable comes from `REFLEX_API_URL` / `REFLEX_DEPLOY_URL`
  (`.env.example`), and production refuses anything but one https origin.
- Append the block below the `---` in `references/conventions_auth.md` to
  `AGENTS.md`, after the scaffold's conventions block (outside the
  `<!-- reflex managed -->` markers, if an older app still has them), with
  `{{app_name}}` filled.
- Add an "Authentication" section to `README.md`: required env vars, how to
  create the admin hash (`uv run python -m {{app_name}}.auth.hash_password`),
  that `/admin-login` is unlinked, that Reflex is pinned and why, and the
  deployment notes from `references/deployment.md` that apply.

## Step 5 — Verify

Same gates as the scaffold, all must pass:

```bash
uv run ruff check --fix . && uv run ruff format .
uv run reflex compile 2>&1 | grep -i deprecat   # must print nothing
uv run pytest -q
uv run mypy .
uv run ruff check . && uv run ruff format --check .
```

Apps from current scaffold versions bundle these in `scripts/check.sh --full`
(every line must read `ok`) and have `scripts/smoke.sh` for the runtime check.

The generated tests are the guards of the architecture — a red one names the
rule that was broken; fix the code, not the test. `tests/conftest.py` brings
a shareable kind of its own (`Probe`), so sharing, merge and delete are
exercised before the app declares any kind.

### Apps from older scaffold versions

- `tests/test_persistence.py` fails with sqlmodel ≥ 0.0.48 ("Datetime values
  must have timezone information"): `models/item.py` has
  `default_factory=datetime.now`. Fix: `lambda: datetime.now(UTC)`.
- `utils/logging.py` without `logging.basicConfig(...)`: every `log.info`
  is dropped, including this skill's `auth.*` events (the audit table still
  records them). Fix: the current scaffold's `configure_logging`.

Both are scaffold files, not auth files: **ask** before fixing them.

Then run it end to end:

```bash
export AUTH_ALLOWED_DOMAINS=<domain> MAIL_TRANSPORT=console
export ADMIN_EMAIL=<addr> ADMIN_PASSWORD_HASH='<from hash_password>'
uv run reflex run
```

and check at least: `/` redirects to `/login`; a link from the server log
signs in and lands on `redirect_to`; the admin entry is invisible to a user
and `/admin` and `/admin/groups` send them to `/forbidden`; `/admin-login`
works (it lands on `/`, with the admin entry now visible) and the admin can
create a group and sees users, sessions and the audit log; a `POST` to
`/_auth/logout` with a foreign `Origin` gets 403; logout returns to `/login`.
Check that the session cookie is `HttpOnly` and that no WebSocket frame
contains its value (DevTools → Network → WS, or a Playwright
`framereceived` listener). Repeated test sign-ins hit the rate limits (5
links per address and per IP in 30 minutes) — that is the app working; raise
`AUTH_LINK_RATE_LIMIT*` for the test run, not in `.env.example`.

## Step 6 — Make the app's data multi-user

Until now every signed-in user reads and changes every row of the app's own
tables. Say so, and **ask** which tables belong to a person and which of
those should be shareable (one `AskUserQuestion`; for a fresh scaffold app
the only candidate is the CRUD demo's `Item`). Reference data everyone may
read and only the admin changes needs no owner — gate its writes with
`admin_event`.

For each table follow `references/ownership_and_sharing.md`: owner column
and share tables, one `Shareable`, read model, use cases that take the
actor, handlers through `call`, the share card, migration. Existing rows
need an owner — ask who gets them. Afterwards the module leaves `LEGACY` in
`tests/test_architecture.py`; when the set is empty, no state queries the
database any more.

If the user wants to stop after Step 5, leave `LEGACY` as it is and note in
`README.md` that the listed modules still serve one shared pot of data.

## Invariants — do not "improve" these

1. Nothing outside `auth/endpoints.py` touches the cookie; nothing outside
   `auth/middleware.py` writes `AuthState`.
2. `AuthState`'s public vars are display values only. Enforcement reads the
   private identity via `auth/policy.py`; handlers get the actor from
   `states/people.actor_id`, never from the browser.
3. `PUBLIC_ROUTES` stays exactly the three login pages unless the user
   explicitly asks; `tests/test_auth_policy.py` pins it and the public
   handlers.
4. Admin is a property of the **session** (password login), not of the
   account. Do not derive it from e-mail address. The admin has no bypass in
   `service/`.
5. All user-facing answers of the link form are identical, whatever happened
   (unknown, foreign domain, blocked, rate-limited, flooding, admin address).
   A new link never invalidates an earlier one; no limit may lock out
   someone who has not misbehaved themselves.
6. App tables reference `authuser.id` by foreign key; every such column is
   declared as ownership or grant (`service/models.py`, `sharing.KINDS`).
7. `service/` never imports `reflex`, `auth/` or the UI packages, and
   returns plain values. Sharing exists once; a new kind is a declaration.
8. The guard tests are not weakened to get green: `LEGACY` only shrinks,
   `OWNER_GATED` and the public surface only change on purpose.
9. `event_origin`, the stripped-flag secret and the upload gate stay as they
   are unless re-verified against the event processor of the Reflex version
   in use.
