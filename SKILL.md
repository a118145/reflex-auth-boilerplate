# Reflex auth boilerplate

Retrofits authentication onto a **reflex-app-scaffold** app. The result:

- **Every page and every event handler requires a signed-in user**, with no
  exceptions except the landing page (`/login`), the admin login
  (`/admin-login`) and `/forbidden`. New pages are protected automatically.
- Users sign in with a **magic link** mailed to an address on an allowed
  domain. Accounts are created on first sign-in.
- One **admin** signs in with e-mail + password (environment only) at an
  unlinked route. A magic link never yields admin rights.
- An **admin area**: live sessions (end them), accounts (block/unblock,
  merge two addresses into one person), audit log.
- Authorization modelled on Reflex Enterprise's auth (secure by default,
  `auth=` checks, `/forbidden`, login redirect with `redirect_to`), built
  without `reflex-enterprise`.

**Read `references/security_model.md` before changing anything** — it
explains why each piece exists. **Read `references/reflex_098_auth_facts.md`
before writing Reflex code** — several obvious approaches silently leak the
session token or simply do not work in Reflex 0.9.8. Also read the scaffold's
own `references/reflex_098_gotchas.md` if it is available.

## Non-negotiables

These are the reason the skill exists. Do not "simplify" them away.

1. **No token, key or password in a public state var — ever.** The session
   token lives only in an HttpOnly cookie; the backend keeps its SHA-256 in
   a `_private` var. Never read `router.headers.cookie`.
2. `AuthMiddleware` is registered at **index 0**. It strips the cookie from
   the router data (Reflex serialises router headers to the browser) and
   gates every event.
3. Sign-in/out are **HTTP endpoints** (`/_auth/*`) driven by `native_form`
   posts, not Reflex events or `rx.form`.
4. The magic link's `GET` only shows a button; the `POST` spends the token
   (mail scanners prefetch links).
5. Links and redirects are built from `api_url`/`deploy_url`, never from
   anything the browser sends. `redirect_to` is same-origin paths only.
6. Authorization is declared in `auth/policy.py` (`PUBLIC_ROUTES`,
   `ROUTE_CHECKS`, `@auth_event(auth=...)`), never as `if` in a handler.

## Step 1 — Inspect the target app

Confirm it is a scaffold app and read off what the templates need. **Ask
nothing the code already answers.**

| Fact | Where |
| --- | --- |
| `app_name` | `rxconfig.py` → `app_name="…"` |
| layout | `ui/nav.py` + `ui/side.py` → `both`; only `nav.py` → `top`; only `side.py` → `side` |
| database | `db_url=` in `rxconfig.py` and an `alembic/` folder |
| `app_title` | the `rx.heading("…")` wordmark in `ui/side.py` (or `ui/nav.py` for `top`) |

Also check, and stop to ask if any is true:

- `auth/`, `pages/login.py`, `ui/account.py` or a `/login` route already exist.
- `git status` is dirty — ask whether to proceed (the edits touch scaffold
  files the user may have changed).
- The anchors in Step 4 are not found verbatim — the user changed the
  scaffold files. Read the file, apply the *intent* of the edit by hand, and
  tell the user what you did.

## Step 2 — Interview

**One `AskUserQuestion` call, three questions.** Do not ask which pages to
protect: all of them are, by design (see Non-negotiables); say so in the
restatement.

1. **Slogan and logo** for the landing page. Offer a neutral default slogan;
   the logo is optional (a file the user names, copied into `assets/`; default
   is the scaffold's `box` icon). Use previews only if it helps.
2. **Allowed e-mail domains** for magic links — exact domains,
   comma-separated (subdomains are *not* included). No default domain;
   require an answer.
3. **Mail transport** to preconfigure in `.env.example`: `smtp` (e.g. a
   Microsoft 365 mailbox), `graph` (Microsoft Graph, app-only), `mailgun`, or
   `console` (development only — logs the link, refused in prod). All four are
   always generated; this only picks the default.

Restate the plan (layout, DB retrofit yes/no, domains, transport, routes
added, that every page will require login) before changing files.

## Step 3 — Database

Magic links need tables. If the app has **no database**:

```bash
uv add "reflex[db]"
```

and in `rxconfig.py` add `import os` above `import reflex as rx` and, inside
`rx.Config(...)`, directly above `default_color_mode=`:

```python
    db_url=os.environ.get("REFLEX_DB_URL", "sqlite:///reflex.db"),
```

Then, for **every** app (with or without a prior database):

```bash
uv run python -c "import greenlet" || uv add greenlet   # SQLAlchemy asyncio needs it; reflex[db] does not pull it in
[ -d alembic ] || uv run reflex db init
```

Do **not** create `models/` for a database-less app: the auth tables live in
`auth/models.py`.

## Step 4 — Copy and wire

### 4a. Copy templates

Copy `templates/` into the app. `tests/*` go to the project's `tests/`,
everything else into the `{{app_name}}/` package, keeping sub-paths. Strip
`.tmpl` and fill placeholders. Never overwrite an existing file.

| Placeholder | Value |
| --- | --- |
| `{{app_name}}` | package name |
| `{{app_title}}` | the wordmark text |
| `{{slogan}}` | a Python string literal — write it with `repr()` semantics (escape quotes) |
| `{{logo}}` | `None`, or a literal like `"/logo.svg"` (file copied to `assets/logo.svg`) |
| `{{show_admin_subnav}}` | `True` for layout `top`, else `False` |

Grep the copied files for `{{` afterwards — nothing may survive.

### 4b. Edit scaffold files

Snippets live in `snippets/`. Each edit names its exact anchor in the
scaffold's original text.

1. **`navigation/routes.py`** — append `snippets/routes_append.snippet`.
2. **`navigation/nav_config.py`**
   - In `class NavItem`, after the `sub_items: …` line, insert
     `snippets/nav_item_admin_only_field.snippet`.
   - Append to `NAV_ITEMS` (last entry): `nav_admin_entry_top.snippet` for
     layout `top`, otherwise `nav_admin_entry_sections.snippet`.
3. **`ui/` — admin entry visible to the admin only, account block at the end
   of the navigation.**
   - `top` (`ui/nav.py`): import
     `from .account import account_block_inline, admin_only`; wrap
     `navbar_item(item, i)` as `admin_only(item, navbar_item(item, i))`;
     in the `left` branch insert `account_block_inline(),` between
     `rx.spacer(),` and `rx.color_mode.button(),`; in the `center` branch
     replace the absolutely positioned `rx.color_mode.button(position=…)` by
     an `rx.hstack(account_block_inline(), rx.color_mode.button(),
     align="center", spacing="3", <same position props>)`.
   - `side` (`ui/side.py`): import
     `from .account import account_block_vertical, admin_only`; wrap
     `_section(item)` as `admin_only(item, _section(item))`; insert
     `account_block_vertical(),` right after the existing `rx.spacer(),`
     (above the colour-mode toggle).
   - `both`: in `ui/nav.py` import `from .account import admin_only` and wrap
     `navbar_item(...)` as above. In `ui/side.py` import
     `from .account import account_block_vertical, admin_only`, wrap the
     `rx.cond(NavState.active_section == index, …)` inside `sections` as
     `admin_only(item, rx.cond(…))`, and after `*sections,` insert
     `rx.spacer(),` and `account_block_vertical(),` — the account block sits
     at the bottom of the sidebar.
4. **`pages/__init__.py`** — import and list in `__all__`: `admin_audit`,
   `admin_login`, `admin_sessions`, `admin_users`, `forbidden`, `login`.
5. **App module `{{app_name}}/{{app_name}}.py`** — after `from . import pages`
   insert `snippets/app_module_imports.snippet`; replace `app = rx.App()` with
   `snippets/app_module_app.snippet`. Update the module docstring: it now also
   wires authentication.
6. **`tests/test_routes.py`** — add `snippets/expected_routes.snippet` to
   `EXPECTED_ROUTES`.
7. **`states/__init__.py`** — leave as is (the admin state is imported by its
   module path). If it is missing, create the scaffold's docstring-only one.

### 4c. Migration, configuration, docs

```bash
uv run reflex db makemigrations --message "auth tables"
uv run reflex db migrate
```

- Write `.env.example` from `snippets/env.example.tmpl`
  (`{{allowed_domains}}`, `{{mail_transport}}`, `{{app_name}}`) and append
  `.env` to `.gitignore`. Never write real secrets anywhere in the repo.
- Append the block below the `---` in `references/conventions_auth.md` to
  `AGENTS.md`, outside the `<!-- reflex managed -->` markers, with
  `{{app_name}}` filled.
- Add an "Authentication" section to `README.md`: required env vars, how to
  create the admin hash (`uv run python -m {{app_name}}.auth.hash_password`),
  that `/admin-login` is unlinked, and the deployment notes from
  `references/deployment.md` that apply.

## Step 5 — Verify

Same gates as the scaffold, all must pass:

```bash
uv run ruff check --fix . && uv run ruff format .
uv run reflex compile 2>&1 | grep -i deprecat   # must print nothing
uv run pytest -q
uv run mypy .
uv run ruff check . && uv run ruff format --check .
```

Known pre-existing failure, not caused by this skill: the scaffold's
`tests/test_persistence.py` fails with sqlmodel ≥ 0.0.48 ("Datetime values
must have timezone information") because the scaffold's `Item.created_at`
uses a naive `datetime.now`. Report it; do not "fix" it here unless asked.

Then run it end to end:

```bash
export AUTH_ALLOWED_DOMAINS=<domain> MAIL_TRANSPORT=console
export ADMIN_EMAIL=<addr> ADMIN_PASSWORD_HASH='<from hash_password>'
uv run reflex run
```

and check at least: `/` redirects to `/login`; a link from the server log
signs in and lands on `redirect_to`; the admin entry is invisible to a user
and `/admin` sends them to `/forbidden`; `/admin-login` works and shows the
admin area; logout returns to `/login`. Check that the session cookie is
`HttpOnly` and that no WebSocket frame contains its value (DevTools → Network
→ WS).

## Invariants — do not "improve" these

1. Nothing outside `auth/endpoints.py` touches the cookie; nothing outside
   `auth/middleware.py` writes `AuthState`.
2. `AuthState`'s public vars are display values only. Enforcement reads the
   private identity via `auth/policy.py`.
3. `PUBLIC_ROUTES` stays exactly the three login pages unless the user
   explicitly asks; `tests/test_auth_policy.py` pins it and the public
   handlers.
4. Admin is a property of the **session** (password login), not of the
   account. Do not derive it from e-mail address.
5. All user-facing answers of the link form are identical, whatever happened
   (unknown, foreign domain, blocked, rate-limited, admin address).
6. App tables reference `authuser.id`; every such table gets a merge hook.
